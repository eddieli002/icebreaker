# Icebreaker Web Game

一個給兩個人使用的手機版破冰聊天遊戲。

打開網頁後選一個聊天深度，就會隨機抽出一張題目卡，兩人輪流回答並自由延伸話題。

**現況：v2 已完成，可直接部署。**

---

## 兩種使用方式

這個 App 刻意同時支援兩種玩法，程式邏輯不偏袒任何一種：

| | 模式 A：話題啟動器 | 模式 B：雙人互動遊戲 |
| --- | --- | --- |
| 情境 | 原本就在聊天，只是想換個話題 | 直接把 App 當成聊天遊戲玩下去 |
| 流程 | 抽一題 → 回答 → 聊開 → 暫時離開 App | 抽一題 → 回答 → 下一題 → 穿插互動卡 → 繼續 |

因此「下一題」保持顯眼，而延伸建議做成使用者主動點擊才出現的次要入口。
聊開了就繼續聊，不需要操作 App；想繼續玩就按下一題；卡住了才用「延伸一下」。

---

## 特色

- 純靜態網站，不需要後端、資料庫或登入
- 5 個聊天層級，共 100 題，每題各有 3 則延伸聊天建議（共 300 則）
- 57 張互動卡，涵蓋找共同點、猜對方、二選一、快速選擇、共同決定、合作挑戰、輕度預測七種類型
- 互動卡依深度分級，Level 1 不會抽到過深的互動，Level 5 也不會一直出現過輕的內容
- 抽題只在選定的層級內，不會玩到一半突然跳到更深的層級
- 抽卡採洗牌牌堆，一輪內不會重複，也不會立即抽到上一題
- 問題卡與互動卡自動穿插，不會退化成一長串問答
- 行動優先設計，大字、大按鈕、單手可操作
- 手機系統返回鍵可回到首頁，不會直接離開網站
- 切換畫面時自動搬移鍵盤焦點，鍵盤與讀螢幕使用者不必重新 Tab
- 零第三方依賴，無任何 npm 套件

## 專案結構

```text
icebreaker/
├── index.html            # 唯一進入點，含首頁與抽卡頁兩個畫面
├── css/
│   └── style.css         # 全站樣式（行動優先、CSS 變數配色）
├── js/
│   └── app.js            # 抽卡邏輯、防重複、穿插規則、延伸建議、畫面切換
├── data/
│   ├── questions.js      # 問題卡題庫（window.ICEBREAKER_QUESTIONS）
│   └── interactions.js   # 互動卡題庫（window.ICEBREAKER_INTERACTIONS）
├── .gitignore            # 排除僅保留於本機的開發文件
├── .nojekyll             # 讓 GitHub Pages 略過 Jekyll 處理
└── README.md             # 本文件
```

### 為什麼題庫是 `.js` 而不是 `.json`

若用 `fetch()` 讀取 `questions.json`，在 `file://` 協定下會被瀏覽器 CORS 政策擋掉，導致直接開啟 HTML 檔時題庫載入失敗。改成 `.js` 並以 `<script>` 掛載全域變數，本機直接開檔與 GitHub Pages 兩種情境都能正常運作，且仍維持純靜態架構。

### 為什麼問題卡與互動卡分成兩個檔案

兩者是不同性質的內容：問題卡讓兩個人「多了解彼此」，互動卡讓兩個人「一起做一件事」。分開放也讓各自維持在可讀的長度，編輯其中一邊時不會干擾另一邊。

## 延伸聊天（Follow-up）

每一題問題卡都附帶三則延伸建議，點擊卡片內的 **💡 延伸一下** 才會出現，
一次顯示一則，依固定順序輪替，三則看完後入口自動收起。

| 順序 | 標籤 | 目的 |
| --- | --- | --- |
| 1 | 往故事聊 | 鼓勵講出具體經驗，而不是停在抽象回答 |
| 2 | 往想法聊 | 了解答案背後的原因、感受或價值 |
| 3 | 換你說說 | 讓另一方也分享，避免變成一個人問、一個人答 |

順序是刻意的：先讓對方講出具體經驗，再談背後的想法，最後才把話題交還給另一個人。

互動卡沒有延伸內容，抽到互動卡時整個入口會被隱藏。

## 本機執行

### 方式一：直接開啟（最快）

用瀏覽器開啟 `index.html` 即可。因為沒有使用 `fetch()`，`file://` 下也能正常運作。

### 方式二：本機 static server（建議）

較貼近實際部署環境：

```bash
cd icebreaker
python -m http.server 8000
```

然後開啟 <http://localhost:8000>。

本機 server 只用於開發測試，網站本身不依賴它。

### 1. 建立 Git repository

```bash
cd icebreaker
git init
git add .
git commit -m "feat: 完成 Icebreaker MVP"
```

### 2. 推送到 GitHub

在 GitHub 建立新的 repository 後：

```bash
git remote add origin YOUR_GITHUB_REPOSITORY_URL
git branch -M main
git push -u origin main
```

### 3. 開啟 Pages

1. 進入 repository 的 `Settings`
2. 左側選單找到 `Pages`
3. Build and deployment 選擇 **Deploy from a branch**
4. Branch 選 **main**，Folder 選 **/ (root)**
5. 儲存

網址格式為 `https://<username>.github.io/<repository-name>/`。

所有資源皆使用相對路徑，因此在 repository 子路徑下可正常運作，**不需要**設定 base URL 或修改任何檔案。

### 版面穩定性（實機回報後補測）

題目的垂直位置由「`card-top` 高度 + 卡片內距 + 類型標籤」決定，全部是定值，因此固定不動：

| 情境 | 題目位置 |
| --- | --- |
| 展開第 1 / 2 / 3 則延伸 | 176px（完全不動） |
| 連抽 60 張，所有問題卡 | 176px（單一值） |
| 連抽 60 張，所有互動卡 | 176px（與問題卡一致） |

最壞情況（最長題目 21 字 + 最長延伸 29 字 + 延伸展開）在各尺寸的表現：

| 螢幕 | 需捲動才碰到「下一題」 |
| --- | --- |
| 320×568（iPhone 5 / 初代 SE） | 是（差 54px） |
| 375×667（iPhone SE 2020/2022） | 否 |
| 390×844（iPhone 12–15） | 否 |
| 414×896（Plus / Max） | 否 |

### 建議在實機補測

自動化測試無法涵蓋觸控手感，建議在實體手機上確認：

- 按鈕是否好按、拇指是否搆得到
- iPhone 瀏海與底部橫條是否遮住內容（已用 `safe-area-inset` 處理）
- 深色模式下的可讀性（目前僅提供淺色主題）

## 修改題庫

編輯 `data/` 底下的檔案即可，不需要任何建置步驟。

### 新增問題卡

在 `data/questions.js` 對應層級的 `questions` 陣列加一筆：

```js
{
  id: 'l1-21',
  text: '題目本文？',
  topic: 'food',
  followUps: {
    story: '往具體經驗延伸的問句？',
    meaning: '往原因、感受或價值延伸的問句？',
    connection: '把話題交還給另一個人的問句？'
  }
}
```

`followUps` 三則若缺其中一類不會壞掉，程式會自動略過該方向；但建議三則齊全，
使用者體驗才一致。題目設計規則：

- 優先使用開放式問題
- 不要像面試
- 不要求敏感個資
- 不假設兩人是情侶、不假設性別或性向
- 每個問題最好能在 5 秒內理解

延伸建議另外還要滿足：避免有明顯「正確答案」、不替回答做心理解讀、一次只延伸目前主題。

### 新增互動卡

在 `data/interactions.js` 陣列加一筆：

```js
{ id: 'ix-58', text: '卡片本文。', type: 'common', depth: [1, 3] }
```

`type` 可用值見檔案開頭註解。`depth` 是 `[最小層級, 最大層級]`，決定這張卡會在哪些
Level 出現；沒有 `depth` 欄位的卡片視為全層級適用。

### 新增層級

在 `levels` 陣列加一筆（含 `id`、`name`、`subtitle`、`questions`），首頁按鈕會自動產生。
若層級超過 5 個，請一併在 `css/style.css` 補上對應的 `--lv6` 色票，否則會退回預設的 `--accent` 色。

### 調整節奏

兩個常數都在 `js/app.js`：

| 常數 | 預設 | 作用 |
| --- | --- | --- |
| `INTERACTION_RATE` | `0.15` | 每次抽卡出現互動卡的機率 |
| `MAX_QUESTIONS_IN_A_ROW` | `6` | 連續幾張問題卡後強制穿插一張互動卡 |

**兩者必須一起調整。** 強制穿插會把互動卡的實際比例推高到機率值以上。
以機率 `p`、上限 `N` 計算，問題卡的平均連續長度為

```text
E[L] = Σ(k=1..N-1) k·p·(1-p)^(k-1) + N·(1-p)^(N-1)
```

互動卡實際佔比即 `1 / (E[L] + 1)`。目前設定的理論值是 19.4%，實測 18.7%。
若把 `MAX_QUESTIONS_IN_A_ROW` 改成 5，比例會升到 21.2%，超出 SPEC 的 10%–20% 區間。

## 已知限制

- 只有淺色主題，尚未支援 Dark Mode
- 重新整理會回到首頁，不保留當前題目（SPEC 明訂不保存使用者資料）
- 沒有「上一題」功能
- 抽題紀錄只存在記憶體，關掉分頁即清空
- 手機實體裝置尚未實測（僅 headless 瀏覽器驗證）
- 延伸建議是固定撰寫的，不會依使用者的回答內容變化（刻意不引入 AI，維持純靜態）
- 三則延伸看完後入口即收起，不循環，也沒有「回看上一則」
- Level 5 可用的互動卡最少（10 張），連續玩很久會比其他層級更早重複
- 320×568（iPhone 5 / 初代 SE）在「最長題目 + 展開最長延伸」的最壞情況下，需捲動才碰得到「下一題」；375×667 以上不受影響
- favicon 以 SVG data URI 提供，極舊版瀏覽器不支援 SVG 圖示時會顯示預設圖示
- 返回鍵支援倚賴 `history.pushState`；若瀏覽器在 `file://` 下擋下該 API，會自動退回「只有 ← 可回首頁」的行為
